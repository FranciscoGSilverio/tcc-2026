# P2 e O2 — plano de implementação

> **Para executores:** SUB-SKILL OBRIGATÓRIA: use superpowers:subagent-driven-development ou superpowers:executing-plans para executar tarefa a tarefa. Os passos usam caixas (`- [ ]`) para acompanhamento.

**Objetivo:** construir os dois níveis de fator que faltam — o plugin de P2 e a sequência segmentada O2 — levando a grade principal de duas células para seis.

**Arquitetura:** os dois entram nas tabelas de `runner/lib/capabilities.mjs`, que desde 21/09 é a fonte única do que um rótulo significa, no mesmo commit que os implementa. O2 encadeia quatro chamadas por identificador de sessão explícito e soma os totais. P2 copia o mesmo `CLAUDE.md` de P1 para `/app` e um diretório de plugin para fora da cópia de trabalho, carregado por `--plugin-dir`, com o carregamento verificado pelo evento de init do transcript.

**Tech Stack:** Node 22, módulos ES, zero dependências novas, Docker para o contêiner de sessão.

**Spec:** `docs/superpowers/specs/2026-09-22-p2-e-o2-design.md` — leia antes de começar.

## Global Constraints

- Nenhuma dependência nova em nenhum `package.json`.
- `seed/`, `hidden-tests/`, `reference/`, `tasks/`, `tools/convention-check/` e `tools/blind-evaluator/` **não são alterados por nenhuma tarefa deste plano**.
- `resultados.csv` e `resultados-piloto.csv` não são tocados. Testes usam dataset temporário via `--dataset` ou `RUNNER_DATASET_PATH`.
- Nenhum arquivo dentro de `/app` pode conter `TCC`, `INATEL`, `harness`, `semente`, `experimento`, `Claude` ou `Anthropic` — `prepare.mjs` aborta a sessão se encontrar. Isso vale para o `CLAUDE.md` de P2, que vai para `/app`.
- O plugin vai para `/opt/plugin`, **nunca para `/app`** — se entrasse na cópia de trabalho apareceria no diff da sessão e contaminaria o script de convenções e o avaliador cego.
- Nomes de plugin e de skills descrevem o projeto, nunca a pesquisa: o agente os enxerga.
- Código e comentários em inglês; documentação, prompts e skills em português.
- `node --test <diretório>` não funciona no Node 24 desta máquina — use glob. Para a suíte completa como portão, use `--test-concurrency=1`, pelo motivo documentado em `tools/blind-evaluator/README.md`.

### Tarefa 1: `readTranscript` soma vários eventos `result`

**Arquivos:**
- Modificar: `runner/lib/transcript.mjs`
- Modificar: `runner/test/transcript.test.mjs`

**Interfaces:**
- Produz: `readTranscript(text)` com a mesma forma de retorno, mas somando sobre todos os eventos `result` presentes em vez de usar só o primeiro.

Pré-requisito de O2: quatro chamadas encadeadas produzem quatro eventos `result` no transcript concatenado. Hoje o leitor pega o primeiro e ignora o resto, o que registraria só o passo 1 e jogaria três quartos da sessão fora.

Regras de agregação: `numTurns`, `costUsd`, os quatro contadores de token e `toolCalls` são **somados**; `stopReason` e `isError` vêm do **último** result, que é o que diz como a sessão terminou; `model` é escolhido pelo maior volume de tokens de saída somado sobre todos os `modelUsage`, que é a regra de 17/09 aplicada ao conjunto; `sessionId` e `cliVersion` vêm do init, como hoje.

if (results.length === 0) {

const last = results[results.length - 1];

// O2 chains four calls, so a session's transcript carries one result per

const sum = (pick) => results.reduce((total, result) => total + (pick(result) ?? 0), 0);

const mergedUsage = {};

    mergedUsage[name] = { ...usage, outputTokens: current.outputTokens + (usage.outputTokens ?? 0) };

}

Cada passo grava `transcript-N.jsonl` em `/out`, e o host concatena os quatro em `transcript.jsonl`, na ordem dos passos — `/out` é montado, então a concatenação acontece no host, sem glob de shell.

- [ ] **Passo 1: implementar a entrega dos passos e o encadeamento**

Em `runner/run-session.mjs`, substitua `runAgent` por:

```js
function deliverPrompt(name, text, containerPath) {
  const staging = mkdtempSync(join(tmpdir(), 'prompt-'));
  const staged = join(staging, 'prompt.txt');
  writeFileSync(staged, text);
  copyIn(name, staged, containerPath);
}

// One call for O1, four chained for O2. Chaining goes through an explicit
// session id rather than --continue: --continue resumes "the most recent
// conversation", which is implicit state of exactly the kind that has
// already produced three defects here (modelUsage[0], content[0], and a
// flag recorded but not honoured).
function runAgent({ name, model, plan, repoRoot, outDir }) {
  const call = (promptPath, sessionFlag, outFile) => {
    const command = [
      'cd /app',
      `claude -p "$(cat ${promptPath})" --output-format stream-json --verbose ` +
      `--max-turns 40 --model ${model} ${sessionFlag} --dangerously-skip-permissions`,
    ].join(' && ');
    return exec(name, ['sh', '-c', `${command} > /out/${outFile} 2>>/out/agent.log`]);
  };

  if (!plan.steps) {
    call('/tmp/statement.txt', '', 'transcript.jsonl');
    return;
  }

  const statement = readFileSync(resolve(repoRoot, plan.statement), 'utf8');
  const uuid = randomUUID();

  plan.steps.forEach((step, index) => {
    const template = readFileSync(resolve(repoRoot, step), 'utf8');
    const prompt = template.replace('{{ENUNCIADO}}', statement);
    const promptPath = `/tmp/step-${index + 1}.txt`;
    deliverPrompt(name, prompt, promptPath);
    const sessionFlag = index === 0 ? `--session-id ${uuid}` : `--resume ${uuid}`;
    call(promptPath, sessionFlag, `transcript-${index + 1}.jsonl`);

    // A step that produced nothing means the chain broke. Carrying on to
    // the next step would produce a session missing a quarter of its work
    // and looking complete, so it fails here instead.
    const produced = join(outDir, `transcript-${index + 1}.jsonl`);
    if (!existsSync(produced) || !readFileSync(produced, 'utf8').trim()) {
      const log = existsSync(join(outDir, 'agent.log'))
        ? readFileSync(join(outDir, 'agent.log'), 'utf8').trim() : '';
      throw new InfrastructureError(
        `O2 step ${index + 1} produced no transcript; agent.log: ${log || '(empty)'}`,
      );
    }
  });

  const joined = plan.steps
    .map((_, index) => readFileSync(join(outDir, `transcript-${index + 1}.jsonl`), 'utf8').trim())
    .join('\n');
  writeFileSync(join(outDir, 'transcript.jsonl'), `${joined}\n`);
}
```

Acrescente `randomUUID` ao import de `node:crypto` e garanta que `mkdtempSync`, `writeFileSync`, `readFileSync`, `existsSync`, `resolve` e `join` já estão importados no arquivo. Atualize a chamada em `main()` para `runAgent({ name, model, plan, repoRoot: REPO, outDir })`.
